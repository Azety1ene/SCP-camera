## 財団について
- 目的は、異常な物品・存在・現象を秘密裏かつ世界規模で封じ込めること。主要各国政府から活動を委任されている
- 任務は **確保(Secure)・収容(Contain)・保護(Protect)**。無力化・破壊は最後の手段
- 情報は「**知る必要性**」に応じて細分化し、必要のない情報にはアクセスしない
- 要注意団体との無承認の協力は懲戒事由。懲戒には「終了」を含む
- 冒頭に「確保、収容、保護。」で始まる、「管理者」署名の訓示文がある

## オブジェクトクラス
- 主要:**Safe / Euclid / Keter**。基準は危険性ではなく「収容の難しさ」
- 判定の目安は「**鍵の掛かった箱テスト**」(箱に入れて放置したら何が起きるか)
- 副次:Thaumiel / Apollyon / Archon / Argus / Cernunnos / Ticonderoga
- 非標準:Explained / Neutralized / Decommissioned / **Pending(情報不足で未割当)** / Uncontained

## セキュリティクリアランス
- レベル0〜5。レベルは上限を示すだけで、個々の情報は「知る必要性」で最小限しか見られない
  - Lv0 事務・守衛 / Lv1 間接的に接する職員 / **Lv2 研究員の大半** / Lv3 上位研究員・機動部隊員 / Lv4 サイト管理者 / Lv5 O5評議会員
- 職員分類 **A〜E**(Aは怪異に一切接触不可、Dは死刑囚などから徴用され毎月記憶処理、Eは初期収容で被曝した者の暫定区分)
- O5評議会員は O5-1〜O5-13 の番号でのみ呼ばれる
- 閲覧には「レベル」と「その情報への必要性」の両方が要る

## 施設
- **サイト**(政府・企業の施設に偽装)と **エリア**(存在自体が秘密の遠隔地)
- 区画は **セクター**(目的別)と **ユニット**(自己封印機能。出入りに完全除染)
- 接頭辞:武装・生物・収容・次元・人間型・保護・臨時・遺物・研究・保管
- **観測所**(Observation Post):小規模で、通信監視やセーフハウスに使う
- 施設番号は廃止後に再利用される

## 機動部隊
- 名称は「機動部隊 + ギリシャ文字 + 番号 + ("愛称")」。愛称は任務を比喩で表す
- 規模は十数名から数百名。任務が終われば休止・解散
- 指揮官(MTFC)、機動部隊申請書がある

## 異常分類システム(ACS)
- 既存のクラスを補強する4つの軸
  - クリアランス(6段階)/ 収容クラス / **撹乱クラス**(Dark → Vlam → Keneq → Ekhi → Amida、影響の広がり)/ **リスククラス**(Notice → Caution → Warning → Danger → Critical、危険度)
- 文書の冒頭に「アイテム番号・レベル・収容クラス・撹乱クラス・リスククラス」を帯のように並べる表示が定番

## サイトへの転用
1. 観測端末の設置先を「**観測所**」として扱い、所属サイトと紐づける
2. 報告書の冒頭を **ACSの帯** にする(収容・撹乱・リスクの3軸を色とアイコンで)
3. 閲覧制限の文言に「**知る必要性**」を使う(レベルが足りていても、必要性がなければ見られない)
4. 職員プロフィールに **職員分類(A〜E)と職種** を出す
5. 施設名は「サイト-81XX(接頭辞)」の形式で作る
6. 情報不足の報告書には **Pending** を使う(生成に失敗したときなどにも自然)
7. 冒頭に「確保、収容、保護。」の標語を置く
