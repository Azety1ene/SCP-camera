# SCP-camera 仕様書

## コンセプト

**財団支給の観測端末。** 身の回りの物にカメラを向けて撮影すると、その物の「SCP報告書(日本支部風)」が生成される。
カメラを、SCPの世界に入り込むための窓として使う。

インスピレーション元:qliminal.jp(映画『Backrooms』公開記念イベントのWebサイト。カメラを使って世界観に没入する体験)

## 体験の流れ

1. **認証**:職員認証端末で合言葉(職員認証コード)を入力し、クリアランスレベルを付与される
2. **観測**:監視カメラ風フィルター越しのカメラ映像に、「異常反応スキャン中」のオーバーレイが重なる
3. **撮影**:シャッターを押すと「財団データベースに照会中…」の演出が入る
4. **報告書**:撮影した物のSCP報告書が表示される。撮影写真は監視カメラ風に加工され、「添付資料」として載る
5. **保存**:報告書を画像として書き出せる。過去の報告書はアーカイブで見返せる

## 財団の社内システムとしての作り込み

界隈の研究(`docs/research/10-site-worldbuilding.md`)をもとに、サイト全体を財団日本支部の社内システムとして作り込んでいる。利用者は統合観測ネットワークの職員という設定。所属は合言葉で決まるクリアランスによって変わる(レベル2は新設の観測所に配属された観測記録部門の職員、O5はO5評議会)。O5には新任職員向けのメールは届かず、書庫のパスコードも不要。既存の人物・団体・カノンは使わず、仕組みだけを借りる。

| 画面 | 内容 |
|---|---|
| `/portal` | 認証後のホーム。配属情報、観測実績と昇格までの件数、未読メール、財団内報。夜間は当直の表示。ごくまれに収容違反の警報(誤報)が鳴る |
| `/library` | 書庫。書き下ろしの内部文書4本(取扱説明書、食堂だより、事故事例集、設置経緯書)。クリアランスとパスコードで閲覧を制限 |
| `/inbox` | 受信箱。着任、初回記録、昇格の辞令、パスコードの通知などが節目に届く |
| `/id` | 職員証。氏名の登録と証明写真の撮影(顔は必ず[編集済み]になる) |

- **クリアランスの昇格:** 収容3件でレベル3、6件でレベル4。報告書の黒塗りは箇所ごとに必要なレベルが決まっていて、昇格するほど読める箇所が増える。すべて読めるのはO5のみ
- **報告書:** ACS(収容・撹乱・リスク)の帯、機密スタンプ、Wikiに倣った「好き / 好きじゃない」の評価
- **小さな仕掛け:** 世界観に合わせた404ページ、タブを離れたときのタイトルの変化、コピー時の持ち出し警告
- 端末内の状態(プロフィール、メール、解錠、評価)は localStorage に保存する
- 受信箱には、いま認証しているクリアランス宛てのメールだけを出す(同じ端末で L2 と O5 を入れ替えても、もう一方宛てのメールは出ない)
- PC では、画面下の F1〜F5 のキーで画面を切り替えられる

## 合言葉とクリアランス

- 合言葉は「職員認証コード」として世界観に組み込む
- **正しいコード**:「認証完了。クリアランスレベル2を付与」→ 観測端末が起動する
- **誤ったコード**:「不正アクセスを検知。記憶処理班が向かっています」など、失敗回数に応じて演出を変える
- **隠しコード(O5権限)**:選考で見てもらう人にはレベル2のコードを渡し、O5のコードはおまけにする

| クリアランス | 報告書の見え方 |
|---|---|
| レベル2(通常) | 物語の核心が黒塗り・`[編集済み]`になり、謎が残る |
| O5(隠し) | 黒塗りが外れて真相が分かる。O5限定の補遺も読める |

- AIには最初から全文を書かせ、伏せる箇所に印を付けさせる。表示時にクリアランスに応じて伏せるので、生成は1回で済む
- 伏せる箇所の印は `[[L3:…]]` `[[L4:…]]` `[[O5:…]]`。AIが物語の中での重さでレベルを決める(軽い手がかりは L3、真相に近い事実は L4、真相そのものは O5)。レベルのない `[[…]]`(仕組みを入れる前の記録)は、報告書の中の出現順に L3 → L4 → O5 へ均等に割り振る
- 読めない箇所は、中身を画面のデータに含めず伏せ字(█)にする(ページ内検索やコピーで読めないように)

### O5の表示切り替え(開発・確認用)

O5で認証した端末だけ、メニューの「表示するクリアランス」で、画面をレベル2・3・4・O5のどれで見るかを切り替えられる。サーバーの認証はO5のままで、変わるのは画面の表示だけ(受信箱はO5のまま)。切り替え中は、ヘッダーに「(O5で表示切替中)」と出る。退出・認証し直しで解除する。

## 報告書の生成

### 構成(出力スキーマ)

- 観測メモ(写真の具体的な特徴。画面には表示しない)
- アイテム番号(`SCP-XXXX-JP`)
- 題名(言葉遊びを含む日本語の題名)
- オブジェクトクラス(Safe / Euclid / Keter など)
- 特別収容プロトコル
- 説明
- 添付資料のキャプション(撮影写真の説明。写り込みへの言及を含む)
- 補遺(記録形式のレパートリーから1〜2個)
- 脚注
- 最後の一文
- O5限定補遺
- 伏せる箇所の印(レベル2では黒塗り、O5では開示)

分量は1,500〜2,500字程度。

### 物語の設計方針

詳細は **`docs/research/00-summary.md`**(有名作品36本の分析のまとめ)に従う。要点:

- 骨格は「平凡な見た目 → ルールを先に・理由は後に → 事例を段階的に積む → 最大の事件 → 注記や手記で感情 → 最後の一文」
- 地の文は冷たく、感情は脚注・注記・手記・手紙に置く
- 写真の**具体的な特徴**(色・傷・印字・周囲に写っている物)を数値や物証にする。写真の端に「何かが写っている」とする手法も使う
- 読後感の型(癒し、笑い→切なさ、切なさ、じわじわ来る不安、ホラー、ルール型の緊張、謎、スケールの飛躍、どんでん返し、メタ)は、サーバー側でランダムに選んで指示する。半分以上は物語寄りの型にする
- 黒塗りは物語の核心に使い、O5で開示する
- 真顔を崩す表現(「面白いことに」、絵文字、「!」の多用)は禁止する
- 自殺・自傷・いじめ・性的な描写・過度なゴア、実在の人物は扱わない
- 既存記事の文章はプロンプトに入れない。抽出した技法と自作の例文だけを使う

### 見本モード(初期設定)

Gemini の混雑が続いたため、UIを先に仕上げる目的で、どの写真を撮っても用意した見本の報告書を返すモードを初期設定にしている。

- 見本は `src/lib/report/samples/` の3件(hydrogen で生成した2件と、どの写真にも合うよう手書きした1件)
- 照会中の演出が見えるよう、6〜10秒待ってから返す
- `REPORT_SOURCE=gemini` を設定したときだけ Gemini で生成する

## 技術構成

| 項目 | 内容 |
|---|---|
| フレームワーク | Next.js(App Router) |
| デプロイ | Vercel |
| AI | Gemini API(無料枠)。SDKは `@google/genai`、JSONスキーマ指定の構造化出力 |
| 生成API | Route Handler `/api/generate`。APIキーはサーバー側の環境変数に置く |
| 認証 | 合言葉をサーバー側で照合し、クリアランス入りの署名付きCookieを発行。`/api/generate` はCookieを確認してから生成する |
| 保存 | 報告書と写真はブラウザ内の IndexedDB。記録の情報(`records`)と画像(`photos`)は別の置き場所に分け、一覧や件数では画像を読まない。利用者が登録したものだけ、財団データベースに送る |
| 財団データベース | 全職員で共有する報告書。本体は Neon(Postgres、表 `shared_reports` は初回に自動作成)、添付画像は Vercel Blob の private のストア(WebP、長辺1280px)。API は `/api/shared`(一覧・登録。一覧は30件ずつ)、`/api/shared/[id]`(取得・削除)、`/api/shared/[id]/image`(添付画像。閲覧した端末にだけ10分キャッシュ)。どれも認証済みのCookieが必要 |
| レート制限 | Neon の表 `rate_limits` で、接続元の IP(ハッシュにして保存)ごとに数える。合言葉の照合は10分に10回、照会は1時間に20回、登録は1日に30回。Gemini での生成は全体で1日300回まで(`GENERATE_DAILY_LIMIT`) |
| カメラ | `getUserMedia`(HTTPS必須)。フィルターは Canvas / WebGL。カメラが2台以上あれば前面・背面を切り替えられる |
| 顔の自動[編集済み] | MediaPipe の顔検出をブラウザ内で動かす。WASM とモデルは自サイトから配信する。顔認識を使えないときは観測画面に表示し、その状態で撮った記録は登録の前にも注意を出す |
| 書き出し | 報告書を画像として保存 |

### 財団データベースの決まり

- 登録できるのは、照会でサーバーが発行した登録票(報告書への HMAC 署名)が正しい報告書だけ。生成していない文章は登録できない。同じ報告書は二重に登録されない
- 登録票には、登録するときの添付画像(加工・縮小済み)の SHA-256 も入れる。照会のときに添付画像も送り、登録のときは同じ画像しか受け付けない。サーバーは画像の中身(先頭のバイト列)で形式を確かめる
- 登録票の有効期限は照会から30日。「後から登録できる」のはこの期間内
- 割り切り: 悪意のある利用者は、照会の時点で顔を隠していない画像を送れる。サーバー側では顔を検出しないので、これは防げない。見つけたら O5 が抹消する
- 送るのは顔を[編集済み]にした添付画像だけ。元の写真と職員の氏名は送らず、観測所の番号(81-OP-XXXX)だけを載せる
- 照会の直後に「登録する / この端末にのみ保存」を選ぶ。端末にのみ保存した記録も、後から報告書の画面で登録できる
- 登録すると、取り下げ用の鍵を登録した端末にだけ渡す(DB にはハッシュを置く)。取り下げると画像も消すが、すでに閲覧した端末には最大10分残る。登録した端末は、報告書の画面・登録された記録の画面・収容記録の「抹消」(端末と財団データベースから / 端末からのみ)で取り下げられる。O5 は鍵なしで何でも抹消できる
- O5 だけが読める部分も含めて全文を返し、黒塗りは表示側(JS)で外す
- 手元の `.env.local` も本番と同じデータベースを指している。テストで登録したものは消す

### 注意点

- Geminiの無料枠では、送信したデータがGoogleの製品改善に使われることがある(規約ページの「データの扱い」に記載している)
- 無料枠の対象モデルと回数制限は変わるので、実装時にGoogle AI Studioで確認する。物語の質がFlash系で足りなければPro系も試す
- 人が写っていても、個人を特定するような内容は書かせない
- ローカルでスマホから試すときは `next dev --experimental-https` などでHTTPSにする
